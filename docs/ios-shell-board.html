1. Stack decision — Capacitor 8

SETTLED

The iOS app is a Capacitor 8 WKWebView shell (frontend/ios/, SPM — no CocoaPods) around the exact same Vite dist/ the web serves. It is the only option where "one codebase" is literal — zero components rewritten.

Capacitor 8 ✓
Wraps frontend/src byte-for-byte. Stable 8.4.2 (Jul 2026), Xcode 26-ready, SPM.
React Native
Every component would need a rewrite — "one codebase" only in spirit.
Flutter
Second codebase in Dart; the pre-V2 Flutter decision predates the web app.

Build loop: npm run build → npx cap sync ios → xcodebuild → simctl install/launch — canonical in CLAUDE.md.

2. Native runtime config + connect screen

SETTLED

Web requests stay same-origin (apiOrigin() → ''); the native bundle loads from capacitor://localhost, so the server origin + API key are runtime config: entered once on a first-run connect screen, verified live, persisted in localStorage. Only lib/nativeConfig.ts imports @capacitor/* — the native surface stays thin.

sequenceDiagram participant App as iOS shell participant CS as Connect screen participant API as DevTrail server App->>App: bootAuth() — no stored config App->>CS: render (NativeSetupRequired) CS->>API: GET /api/v1/stats (Bearer key, no credentials) API-->>CS: 200 OK CS->>CS: persist origin + key, reload App->>API: all queries (Bearer, credentials omitted) API-->>App: live data

Logout on native = full disconnect (clears origin + key → back to connect screen).

4. Bugs found & fixed (all regression-tested)

SETTLED

❌ credentials: 'include' natively

Backend CORS answers Access-Control-Allow-Origin: * — browsers reject credentialed cross-origin responses to a wildcard. Every native query died; Home rendered empty (the probe worked because it omits credentials).

✓ fetchCredentials()

Native = 'omit' (Bearer key only, no cookies). Web keeps 'include' for the Easy Auth session. Pinned by nativeConfig.test.ts.

pg pool crash (pre-existing): no 'error' listener on pg.Pool — one dropped idle connection killed the whole server (twice, during a docker-Postgres crash/recovery). Now logs + continues; proven live by restarting Postgres under the running backend. Test: backend/tests/unit/db/client.test.ts.
iOS input auto-zoom (found by ios-smoke): text controls under 16px make iOS zoom the whole viewport on focus — and the zoom sticks, leaving the app scaled/panned. Inputs are now 16px on touch devices (also fixes iPhone-Safari web); desktop keeps compact type.
Safe-area trap: the mobile .topbar rule's padding shorthand reset the base safe-area padding-top → crumb under the iOS status bar. Pattern: calc(14px + var(--safe-area-inset-top, env(safe-area-inset-top, 0px))).

5. Web parity verification

SETTLED

The web app is behaviorally untouched: every native branch is gated on isNativeApp(), and apiOrigin()/fetchCredentials() return the pre-existing web values outside Capacitor.

  • make ci green — typecheck, 85 frontend unit tests (15 new), 4 backend db tests (1 new regression), production build.
  • Full Playwright suite (make e2e): 227 passed, 6 failed, 1 flaky (23 min). All 6 failures attributed to pre-existing local-environment issues, none to this branch: doc-preview/search/settings pass on a quiet rerun (they fell in a Postgres crash-recovery window), and personal-todos-drawer + counters fail/flake identically on main (A/B, interleaved runs, same stack).
  • Engine + native parity layers: the webkit-mobile Playwright project reruns curated mobile workflows on WebKit (in make ci-full), and make ios-smoke drives the real simulator end to end (fresh install → connect → UI todo create → REST verify). Both green: 94 passed across the mobile projects, smoke passes repeatably.

Local-run caveat: the shared dev Postgres has been crash-looping since Jul 29 (pre-existing, see docker logs — spun out as its own task); cloud CI (make ci-full on merge) is the authoritative gate per the repo's CI model.
