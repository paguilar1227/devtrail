1. Audit findings

SETTLED

Before this work the suite had 110 desktop tests against 14 mobile tests. Five surfaces had no coverage on either device: the Archived view, tag detail + rename, Projects-page filters, the whole Project tab set (Chat / Documents / Notes / Todos), and the command palette.

Cross-device gaps: Trash, tag detail/rename, Projects filters + grid/list, project tabs, activity-page filters, palette, theme shortcut/persistence.
Mobile-only gaps: home dashboard flows, notes/todos view workflows, doc reader previews, upload modal, project hero actions, More→Todos nav.

2. Parity approach

SETTLED

Shared workflow suites in tests/e2e/shared/*.ts are invoked by thin specs in both device trees, so one workflow definition runs under both Playwright projects — parity by construction. A device-aware nav helper (helpers/nav.ts) absorbs the sidebar-vs-tabbar/More-sheet split.

Fixtures are arranged over REST with e2e:-stamped names (swept by the standard teardown); assertions are presence/relative, never absolute seed counts; no waitForTimeout anywhere. Specs that search fresh content gate on ingest readiness first.

3. Inert-UI gaps — found, then FIXED (see §6)

SETTLED

The audit compared every rendered control against its handler. These render but do nothing — testing them would pin dead UI, so they're documented as product work instead:

  • Archived view: Restore · Delete forever · Empty archive buttons
  • Tags rows: ⋯ menu (Rename works and is tested)
  • Projects list view: per-row ⋯ menu
  • Project Todos tab: filter chips, Top/Sub pill, "Add details"
  • Project Notes tab: Pinned / Processing chips
  • Chat citations: "Open source" · Docs bulk bar: "Tag", "Move to project"

Zero flakiness, zero retry budget: three consecutive full-suite runs (both device projects) with retries disabled — 234 passed each time (212 in the earlier parity-pass runs, before the intent-fix regressions were added). The remaining 2 are the justified mobile skips (doc row actions are hidden below 820px by design); the 2 pre-existing test.fail markers for the unimplemented Notifications/Help views pass as expected failures.

Two product bugs fixed on the way (see §3 detail doc): the RAG citation schema drift that broke the Chat tab for every cited answer (prod included), and the long-parked "~26 flaky" Playwright defect — hooks registered as helper-module side effects only attach to the first spec file per worker; every later file's first test ran hook-less on about:blank. The suite now uses fixture-based hooks, immune to module caching.

Historical drag-to-reorder flake also made deterministic (gate on dnd-kit's aria-pressed activation + bounded re-attempt): 8/8 under --repeat-each.
